## Next.js version warning

This project runs **Next.js 16.4 / React 19.3**, which is newer than most training data. Before writing Next.js code, read the relevant guide in `node_modules/next/dist/docs/` (`01-app/` covers the App Router) and follow its deprecation notices. `AGENTS.md` is regenerated by `next dev`; don't remove it.

`next.config.ts` enables `cacheComponents` and `partialPrefetching`, so data fetching and caching follow the Cache Components model (check the docs for `"use cache"` and Suspense requirements rather than assuming older `fetch`/`revalidate` behavior). Route props use the generated global types such as `LayoutProps<"/">` / `PageProps<...>`.

## Commands

```bash
npm run dev          # dev server on http://localhost:3000
npm run build        # production build
npm run lint         # ESLint (flat config, next core-web-vitals + typescript)
npm run typecheck    # tsc --noEmit

npm run db:generate  # drizzle-kit: create SQL migration in ./drizzle from schema
npm run db:migrate   # apply migrations
npm run db:push      # push schema directly (no migration files)
npm run db:studio    # Drizzle Studio
npm run db:seed      # load the sample catalogue (idempotent; upserts by slug)

npm run auth:generate  # Better Auth CLI: generate auth tables into src/db/auth-schema.ts
```

There is no test framework set up yet.

Copy `.env.example` to `.env` and fill in `DATABASE_URL` (Neon pooled connection string), `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`. Both `src/db/index.ts` and `drizzle.config.ts` throw at import time if `DATABASE_URL` is missing.

## Architecture

- **App Router** under `src/app/`; the `@/*` path alias maps to `src/*`.
- **Database**: Neon serverless Postgres over HTTP (`@neondatabase/serverless` + `drizzle-orm/neon-http`). The single `db` instance lives in `src/db/index.ts` and is built with the full schema from `src/db/schema.ts`, a barrel that re-exports every table file and is the only schema file drizzle-kit reads. Migrations output to `./drizzle` and are committed.
- **Catalogue**: `src/db/catalog-schema.ts` defines `categories` → `products` → `product_stock`. `src/lib/products.ts` reads them; `src/lib/catalog.ts` holds the `Product` types, price/stock helpers and editorial content (not product data).
- **Auth**: Better Auth.
  - Server config: `src/lib/auth.ts` (Drizzle adapter, `provider: "pg"`, passed the same schema module). `nextCookies()` must stay the **last** plugin.
  - HTTP handler: `src/app/api/auth/[...all]/route.ts` mounts it at `/api/auth/*`.
  - Client: `src/lib/auth-client.ts` exports `authClient` (React) for use in client components.
  - Auth tables are not defined yet; `npm run auth:generate` writes them to `src/db/auth-schema.ts` (overwriting only that file). Then add `export * from "./auth-schema";` to `src/db/schema.ts`. After changing auth config/plugins, regenerate, then `db:generate` + `db:migrate` (or `db:push`).
- **Styling**: Tailwind CSS v4, loaded through a Turbopack loader rule (`@tailwindcss/turbopack` in `next.config.ts`) rather than PostCSS. Theme tokens are defined CSS-first in `src/app/globals.css` via `@theme inline`; there is no `tailwind.config` file.
- **Design system** (all in `src/app/globals.css`): monochrome and image-led. Tailwind's default colour palette, radii and shadows are **reset**, so only system tokens exist: `foreground`, `background`, `surface`, `surface-image`, `muted`, `divider`, `backdrop`, `focus`, `error`, `success`, `warning`, plus `black`/`white`. Wrap a section in `.inverse` (or `data-inverse`) to flip it to white-on-black.
  - Type: use the `type-*` utilities (`type-detail`, `type-caption[-strong]`, `type-body[-strong]`, `type-lead`, `type-title-xs…xxl`, `type-display`) rather than raw `text-*`/`font-*`; they scale up at `lg`. Titles are uppercase. Font is Outfit via `next/font` (`--font-outfit`) in `src/app/layout.tsx`.
  - Layout: `container-page` (max 90rem, 16/32/64px gutters), `container-bleed`, `container-prose`, `section` (48/96px vertical), `grid-products` (2/3/4 cols), `grid-split`, `media-product` (4:5, contained), `media-hero` (3:4 → 16:9, cropped).
  - Controls: `btn` + `btn-primary` | `btn-secondary`, with `btn-block` / `btn-block-mobile`; `link` (underlined) and `link-quiet` (underline on hover / `aria-current`); `divider` for 1px rules. Corners are square; 2px (`rounded-xs`) only on controls.

## Database conventions

- **Scope**: the schema is deliberately limited to products, categories and stock. Don't add carts, orders, payments, reviews, wishlists or product variants without being asked.
- **Schema files**: one `src/db/<domain>-schema.ts` per area, re-exported from `src/db/schema.ts`. Never define tables in `schema.ts` itself; `auth-schema.ts` is generated, so don't hand-edit it.
- **Migrations**: change the schema, run `db:generate`, review the SQL in `./drizzle`, then `db:migrate`. Commit the migration files and never edit one that has been applied. Don't use `db:push` against the shared database.
- **Seed**: `src/db/seed.ts` must stay idempotent (upsert by slug, replace child rows). Update it whenever the schema changes.
- **Table design**:
  - Integer identity primary keys internally; `slug` (unique) is the public key used in URLs and forms.
  - snake_case column names, `timestamptz` `created_at` / `updated_at`.
  - Money is integer minor units (pence); currency is the `CURRENCY` constant, not a column.
  - Ordered child rows get a `position` column.
  - Stock is per size in `product_stock` (`quantity` with a `>= 0` check). A size is a stock row, not a variant: it has no price of its own.
  - JSONB only for data that is always read with its parent and never queried alone (product `images`); anything that is updated or queried independently gets its own table.
  - Foreign keys: `restrict` for reference data (categories), `cascade` for owned children (stock).
- **Reads**: pages and components never import `db`. They call functions in `src/lib/products.ts`, which use `"use cache"` + `cacheLife("minutes")` + `cacheTag("products")` and map rows to the plain `Product` shape. Purchase-critical checks (live stock in `addToBag`) read uncached.
- **Writes**: anything that changes products or stock must invalidate the `products` tag (`updateTag` in server actions, `revalidateTag` elsewhere).
- **Neon HTTP driver**: no interactive transactions; use `db.batch([...])` or sequential idempotent statements.
- **Relational queries** (`db.query.*`): raw `sql` in `where`/`orderBy` has every column aliased to the root table, so a subquery on another table silently breaks. Look the value up in a separate query first.
- **Build**: `next build` queries the database (`generateStaticParams` must return at least one slug), so `DATABASE_URL` must be set at build time.
